# Decisions

Every assumption or value the plan does not define is recorded here (per Agent Instructions rule 2). Nothing clinical is presented as medical fact.

## 2026-11-13 — Phase 1

1. **Docker excluded by owner instruction (2026-11-13).** Docker is not installed in this VM and the owner said to ignore it completely: no install attempt, no `docker-compose up` verification, Docker is not a blocking acceptance item. `docker-compose.yml` and the Dockerfiles are written as config only, unverified.
2. **Password policy (plan says "minimum password policy", no values).** Minimum 12 characters, at least one uppercase, one lowercase, one digit, one special character. Enforced server-side on user creation and password change. Recorded here; changeable by owner.
3. **Password hashing.** argon2-cffi (`argon2.PasswordHasher`, default params) — plan allows bcrypt or argon2.
4. **MFA flow.** Login for a role that requires MFA returns HTTP 200 with `success: true`, `data: { "mfaRequired": true, "mfaToken": "<short-lived JWT, 5 min>" }` and no access/refresh tokens. The client then calls `POST /auth/mfa/verify` with the TOTP code and the mfaToken to receive tokens. MFA setup: `POST /auth/mfa/setup` (returns TOTP secret + otpauth URL; user scans with an authenticator app), `POST /auth/mfa/confirm` (verifies a code, then enables MFA). MFA is required for Super Admin, Branch Admin, Medical Officer, Lab In-charge (per Security section).
5. **Lockout.** After 5 failed login attempts the account locks for 15 minutes (both values are Settings keys `security.lockout_threshold` / `security.lockout_minutes_minutes`, seeded as defaults). Failed attempts are counted per user; the counter resets on a successful login.
6. **Rate limiting.** slowapi, in-memory. Defaults: login 10/minute per IP, other auth endpoints 30/minute, writes 60/minute per IP. Test settings raise these limits (see tests/conftest.py) so the suite is not flaky; the limiter itself is unit-tested with a low limit.
7. **Branch switching.** `POST /auth/switch-branch` with `{branchId}` returns a fresh access token (15 min) whose `branch_id` claim is the new branch. The refresh token is unchanged. The user must be assigned to the target branch (Super Admin may switch to any branch).
8. **Branch scope in tokens.** Access tokens carry `branch_id` (the user's active branch) and `branches` (all assigned branch ids). Super Admin has `branches: ["*"]` and may access any branch. Non-admin users see only their assigned branches; a record outside scope returns 404 (never reveals existence).
9. **Barcode format.** `BB-YYYYMMDD-XXXXXX` where `XXXXXX` is 6 characters from Crockford base32 (no 0/O, 1/I/L ambiguity), generated server-side with a DB uniqueness check and retry on collision. Uniqueness is enforced by a DB unique constraint; barcodes are never reused. Format documented here, not in the plan.
10. **Seed donor/camp tables.** The plan's Phase 1 seed script requires 200 fake donors and sample camps, but no donor features are built in Phase 1. Minimal `donors` and `camps` tables exist ONLY to hold seed demo data; there are no routers, services, screens, or API endpoints for them in Phase 1. They will be built properly in Phase 2.
11. **Settings model.** `Setting` rows have `key`, `value` (JSON), `scope` (`global` | `branch`), `branch_id` (null for global), `confirm_with_mo` (bool, true for clinical defaults), `label`, `description`. Lookup is branch value first, then global fallback. All clinical defaults (eligibility, gaps, shelf life) are seeded with `confirm_with_mo: true` and the settings screen labels them "Default — confirm with Medical Officer before go-live".
12. **Roles/permissions model.** `Role` rows seed the 10 roles from the RBAC table. `Permission` rows are `resource:action` strings (e.g. `branches:create`). `RolePermission` maps roles to permissions. The RBAC table in the plan is the authority; the mapping is seeded from it and listed in `apps/api/app/core/rbac.py`.
13. **Audit logging.** Service-layer helper `audit_log()` is called on every create/update/soft-delete/status change, recording user, action, entity, entity id, old/new values (JSON), timestamp, IP, branch. There is no edit/delete API for audit entries. `GET /audit-logs` is Admin/Auditor only.
14. **Masters model.** One `MasterData` table with `type` (blood_group, component_type, test_name, deferral_reason, discard_reason, hospital, ward, charge), `code`, `name`, `extra` (JSON, e.g. charge amount in paise), `is_active`, `branch_id` (null = global master). CRUD per type at `/masters/{type}`.
15. **Money.** Charges store `amount_paise` (integer) in `extra`. No floats anywhere.
16. **Timestamps.** Stored in UTC; ISO 8601 strings ending in `Z`.
17. **Frontend UI components.** shadcn/ui style components are hand-written in `apps/web/src/components/ui/` (button, input, card, table) — same API as shadcn/ui primitives, no shadcn CLI dependency.
18. **Seed data.** All seed data is fake (Faker-style invented Indian names, fake mobiles in 90000xxxxx range, fake addresses). One Super Admin: `admin@bloodbank.local` / password set via env `SEED_ADMIN_PASSWORD` (default `Admin@123456` documented in .env.example as a DEV-ONLY default to change). 3 demo branches, 200 fake donors, sample camps.
19. **Refresh tokens.** Stored hashed (SHA-256 of the token) in `refresh_tokens` with `jti`, `user_id`, `expires_at`, `revoked_at`, `replaced_by`. Rotation: each refresh revokes the old token and issues a new one. Logout revokes the presented refresh token. Revocation list is checked on every refresh.
20. **CORS.** Strict allowlist from env `CORS_ORIGINS` (default `http://localhost:3000` for dev). Never `*`.
21. **CORS allowlist extended (2026-11-13).** Added `http://127.0.0.1:3000` alongside `http://localhost:3000` in the dev `.env` after the Playwright E2E showed the browser origin `http://127.0.0.1:3000` being blocked. Still an explicit allowlist, never `*`.
22. **Frontend fetch-wrapper bug — found by E2E, fixed (2026-11-13).** openapi-fetch calls a custom `fetch` with a fully-built `Request` object. The original `authFetch` re-wrapped it as `fetch(input, { headers: new Headers(...) })`, which per the Fetch spec replaces the request's header list — silently dropping `Content-Type: application/json` (the API rejected every browser login with `VALIDATION_ERROR`) and `Authorization`. Fixed by normalising to `new Request(input, init)` once and mutating its headers in place; the 401 retry uses a pre-fetch `request.clone()`. The bug was invisible to curl checks — only the browser E2E caught it.
23. **E2E admin MFA handling (2026-11-13).** The seed Super Admin is an MFA-required role, so the Playwright test performs the real MFA setup/verify flow in the browser (reads the setup secret from the screen, computes TOTP inline with `node:crypto` — no new dependency). `e2e/global-setup.ts` resets MFA on all Super Admins in the dev DB before each run so the test starts from a known state. The TOTP secret is never written to disk or the report. After an E2E run, MFA is left enabled on the seed admin (plan-required state); a password-only admin login is not possible by design. Reset SQL: `UPDATE users SET mfa_enabled=false, mfa_secret=NULL FROM roles WHERE users.role_id=roles.id AND roles.name='Super Admin';`
24. **Ruff excludes generated Alembic migrations (2026-11-13).** `alembic/versions` added to `[tool.ruff] exclude` — Alembic generates the file header/imports, which trip W291/UP035/I001/UP007. Migrations are still applied and tested.
25. **Playwright artifacts git-ignored; duplicate spec removed (2026-11-13).** `test-results/` and `playwright-report/` added to `apps/web/.gitignore`. The stray duplicate `apps/openapi.json` (identical copy of the root spec) was deleted; the canonical spec is the repo-root `openapi.json` (also copied to `apps/api/openapi.json` by the export script).
